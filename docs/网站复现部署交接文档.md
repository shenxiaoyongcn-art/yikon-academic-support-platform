## 1. 项目基本信息

### 1.1 网站是做什么的

Yikon 学术支持管理平台是一个面向辅助生殖、PGT、生殖遗传、NGS 和 IVD 学术业务的一体化管理中台，当前包含：

- 管理总览；
- 招标中心：对接 Synology 云盘资料库；
- 科研项目管理：预留 BMP / CRM 同步；
- 售后闭环：预留 BMP / CRM 同步；
- 推广会议：过程管理与效果复盘；
- 数据分析与汇报：产品、医院、人员及医检所运营指标分析，支持生成 PPT；
- PGD 资质评审：全国单位目录、省份汇总、申报/筹建/试运行/正式运行阶段管理；
- 遗传咨询培训：课程、考试、能力与个案实训管理。

### 1.2 技术栈

| 层级 | 技术 | 作用 |
|---|---|---|
| UI | React 19.2.6 | 页面组件和交互 |
| Web 框架 | Next.js 16.2.6 App Router | 路由、服务端组件和 API Route |
| 构建适配 | Vinext 1.0.0-beta.3 + Vite 8.0.13 | 将 Next.js 应用构建为 Cloudflare Worker 兼容产物 |
| 样式 | Tailwind CSS 4.2.1 + `app/globals.css` | 全局样式和响应式布局 |
| 数据访问 | Drizzle ORM 0.45.2 | D1 / SQLite 表结构与访问 |
| 数据库 | Cloudflare D1（SQLite 语义） | 运营数据、同步记录与审计数据 |
| PPT | PptxGenJS 4.x | 浏览器端生成季度汇报 PPT |
| 部署 | OpenAI Codex Sites | 构建归档、版本管理和线上发布 |
| 底层运行 | Cloudflare Workers | 前端 SSR、API 和 D1 绑定的运行环境 |
| 源码管理 | GitHub | 代码、版本和自动检查 |
| 辅助脚本 | Python 标准库 | 从本地 XLSX 生成 PGD 单位 JSON；不参与网站生产运行 |

## 4. 从零开始部署：新电脑完整步骤

以下以 macOS / Linux 为主。Windows 建议使用 WSL2；也可以在 PowerShell 中执行等价命令。

### 第 1 步：准备账号

对方需要：

1. GitHub 账号，用于读取代码；
2. 可运行 Codex 的 ChatGPT / OpenAI 账号；
3. Codex 中可用的 Sites 能力；
4. 如果复用当前线上站点，由当前所有者把对方加入站点编辑者；
5. 若需外部接口，向 IT 申请独立服务账号和服务 Token，不要复制个人密码。

### 第 2 步：安装基础软件

安装 Git：<https://git-scm.com/downloads>

安装 NVM：<https://github.com/nvm-sh/nvm>

安装完成后关闭并重新打开终端，再执行：

```bash
git --version
nvm --version
```

成功时会显示版本号。

### 第 3 步：下载代码

```bash
git clone https://github.com/shenxiaoyongcn-art/yikon-academic-support-platform.git
cd yikon-academic-support-platform
git switch main
git status
```

成功时应看到：

```text
On branch main
nothing to commit, working tree clean
```

### 第 4 步：安装固定版本的 Node.js 和 pnpm

```bash
nvm install 22.13.0
nvm use 22.13.0
corepack enable
corepack prepare pnpm@11.19.0 --activate
node --version
pnpm --version
```

预期版本：

```text
v22.13.0
11.19.0
```

### 第 5 步：安装项目依赖

必须在包含 `package.json` 的项目根目录执行：

```bash
pnpm install --frozen-lockfile
```

此步骤通常需要等待 1～5 分钟。成功时不会出现红色错误，并会生成 `node_modules/`。

### 第 6 步：创建本地环境变量文件

macOS / Linux：

```bash
cp .env.example .env.local
```

Windows PowerShell：

```powershell
Copy-Item .env.example .env.local
```

然后用文本编辑器打开 `.env.local`。只填写自己获得的新凭证，不要把该文件提交到 GitHub。

如果只想查看页面，不测试 Synology、BMP 和医检所接口，可以先保持这些接口变量为空。

### 第 7 步：初始化本地 D1 数据表

```bash
pnpm db:migrate:local
```

成功时会提示 migration 已应用。本地数据库写在被 Git 忽略的 `.wrangler/` 目录中。

### 第 8 步：本地运行

```bash
pnpm dev
```

看到类似以下提示时表示启动成功：

```text
Local: http://localhost:3000
```

浏览器打开：<http://localhost:3000>

停止本地服务器：在终端按 `Ctrl + C`。

### 第 9 步：执行交付前检查

```bash
pnpm lint
pnpm build
```

两个命令都必须成功。生产构建完成后会生成 `dist/`，该目录不需要提交。

### 第 10 步：部署到当前 Sites 项目

前提：对方已获得当前 Sites 项目的编辑者或所有者权限。

在 Codex 中打开本项目，然后复制以下提示给 AI：

```text
请使用项目现有的 .openai/hosting.json 和 Sites 托管配置部署当前 main 分支。
先执行 pnpm install --frozen-lockfile、pnpm lint 和 pnpm build；检查通过后，
把同一个已验证提交同步到 Sites 源码仓库，保存新版本，并沿用当前访问权限发布。
不要新建重复站点，不要修改站点公开范围，不要在日志或文件中输出任何环境变量值。
发布成功后返回线上地址。
```

Sites 发布完成后，打开：

<https://yikon-academic-support.calm-chick-8425.chatgpt.site>

依次点击左侧八个导航入口，确认都能打开。

### 第 11 步：没有当前站点权限时，新建独立副本

不要尝试复用无权访问的项目，也不要复制临时部署 Token。将仓库复制到一个独立目录，在 Codex 中打开，然后使用：

```text
我要把这个仓库部署成我自己账号下的新 Sites 项目。
请先读取项目结构和 .openai/hosting.json，但不要尝试写入原站点；
为副本创建一个新的 Sites 项目，绑定一个逻辑名为 DB 的 D1 数据库，
把新的 project_id 写回副本的 .openai/hosting.json，配置我提供的环境变量，
执行 lint 和生产构建后发布。不要复制或显示旧站点的任何密码或 Token。
```

新副本会获得新的 `chatgpt.site` 地址。原站点的用户权限、环境变量和 D1 数据不会自动复制。

## 6. 环境变量

真实值只配置在本地 `.env.local` 或 Sites 环境变量中，不得写入本文、源码、聊天记录或 GitHub。

```text
SYNOLOGY_BASE_URL=<Synology 的 HTTPS 地址>
SYNOLOGY_USERNAME=<只读服务账号>
SYNOLOGY_PASSWORD=<服务账号密码>
SYNOLOGY_ROOT_FOLDER=<允许检索的根目录>

BMP_BASE_URL=<BMP HTTPS API 网关>
BMP_SERVICE_TOKEN=<BMP 服务 Token>
BMP_RESEARCH_PATH=/api/v1/research-projects
BMP_AFTERSALES_PATH=/api/v1/aftersales-tickets
BMP_EVENTS_PATH=/api/v1/academic-events
BMP_SALES_ANALYTICS_PATH=/api/v1/sales-analytics
BMP_PGD_REVIEW_PATH=/api/v1/pgd-reviews
BMP_PGD_CENTERS_PATH=/api/v1/pgd-centers
BMP_TRAINING_PATH=/api/v1/genetic-counseling-training

MEDICAL_LAB_BASE_URL=<医检所 HTTPS API 网关>
MEDICAL_LAB_SERVICE_TOKEN=<医检所服务 Token>
MEDICAL_LAB_METRICS_PATH=/api/v1/hospital-operation-metrics

PLATFORM_ADMIN_EMAILS=<管理员邮箱，多个用英文逗号分隔>
```

| 变量 | 用途 | 是否敏感 | 获取方式 |
|---|---|---:|---|
| `SYNOLOGY_BASE_URL` | Synology DSM / File Station 地址 | 否 | NAS 管理员提供；必须为 HTTPS |
| `SYNOLOGY_USERNAME` | 服务端搜索云盘的只读账号 | 是 | NAS 管理员新建最小权限服务账号 |
| `SYNOLOGY_PASSWORD` | 上述账号密码 | 是 | NAS 管理员安全发送；建议定期轮换 |
| `SYNOLOGY_ROOT_FOLDER` | 平台允许搜索的根目录 | 否 | NAS 管理员确认权限边界 |
| `BMP_BASE_URL` | BMP API 网关 | 否 | BMP / IT 团队提供 |
| `BMP_SERVICE_TOKEN` | BMP Bearer Token | 是 | IT 新建服务身份，不使用个人 Token |
| `BMP_*_PATH` | BMP 各模块资源路径 | 否 | 按 Swagger / Postman 调整；默认值可保留 |
| `MEDICAL_LAB_BASE_URL` | 医检所 API 网关 | 否 | 医检所系统负责人提供 |
| `MEDICAL_LAB_SERVICE_TOKEN` | 医检所 Bearer Token | 是 | 医检所系统负责人新建服务 Token |
| `MEDICAL_LAB_METRICS_PATH` | 医院运营指标路径 | 否 | 按接口文档调整 |
| `PLATFORM_ADMIN_EMAILS` | 允许维护 PGD 运营数据和触发同步的管理员 | 个人信息 | 由部门负责人确认，多个邮箱用英文逗号分隔 |

当前线上只配置了 Synology 相关变量和管理员名单；BMP 与医检所变量尚未配置。交接时只交付变量名和获取方式，真实值必须由原所有者通过安全渠道重新录入或由 IT 重新签发。

## 7. 第三方服务

### 7.1 Codex Sites / Cloudflare Workers

- 用途：托管前端、服务端 API、版本和 D1 绑定。
- 是否需要重新注册：复用原站点需要 Sites 编辑权限；新建副本需要对方自己的可用账号。
- 不能直接复制：短期源码写入凭证、发布 Token、登录态。
- 可以复制：代码、migration、`.openai/hosting.json` 的逻辑结构。

### 7.2 Cloudflare D1

- 用途：运营指标、同步台账、审计、项目数据。
- 当前绑定：`DB`。
- 当前状态：15 张表均已创建，线上表当前为空。
- 新副本：由 Sites 新建并绑定 D1，随部署应用 `drizzle/` migration。
- 不能直接复制：旧 D1 的内部资源标识和访问凭证。

### 7.3 GitHub

- 用途：源码、版本历史、Pull Request 和自动构建检查。
- 仓库：<https://github.com/shenxiaoyongcn-art/yikon-academic-support-platform>
- 分支：`main`。
- 自动检查：`.github/workflows/ci.yml` 使用 Node 22.13.0、pnpm 11.19.0 执行 `pnpm lint` 和 `pnpm build`。

### 7.4 Synology NAS

- 用途：招标资料原文件库和证据搜索。
- 平台通过 `SYNO.API.Auth`、`SYNO.FileStation.List`、`SYNO.FileStation.Search` 在服务端访问。
- 新接手人需要新的只读服务账号，不能从 Git 仓库复制密码。
- 平台不把登录 SID 落库，每次搜索后都会退出会话。

### 7.5 BMP

- 用途：科研、售后、会议、销量分析、PGD 评审、PGD 运营和培训数据源。
- 当前状态：连接器、鉴权头、分页与增量参数已完成；生产网关、Token 和字段映射尚未提供。
- 对方需要取得：Swagger / Postman、数据字典、状态字典、脱敏样例、测试账号或服务 Token。

### 7.6 医检所系统

- 用途：医院维度的样本量、扩增成功率、阳性率、阴性率和嵌合率。
- 当前状态：连接器与同步入口已完成，生产接口尚未配置。
- 对方需要取得：接口地址、指标口径、分子分母、数据周期、脱敏样例和服务 Token。

### 7.7 登录认证

- Sites 在请求头中注入已认证用户 ID、邮箱和姓名。
- `app/chatgpt-auth.ts` 读取这些请求头。
- `PLATFORM_ADMIN_EMAILS` 决定管理员权限。
- 不需要 OpenAI API Key，也不要自行伪造认证请求头。

### 7.8 当前未使用的服务

项目没有使用 Supabase、Firebase、Vercel、Railway、Render、支付、邮件发送、OpenAI / Claude / Gemini API 或对象存储 R2。

## 8. 数据库

## 13. 常见报错和解决方法

### 13.1 `node: command not found`

原因：未安装或未启用 Node.js。

```bash
nvm install 22.13.0
nvm use 22.13.0
node --version
```

### 13.2 `pnpm: command not found`

```bash
corepack enable
corepack prepare pnpm@11.19.0 --activate
pnpm --version
```

### 13.3 `ERR_PNPM_OUTDATED_LOCKFILE`

原因：`package.json` 和锁文件不一致，或使用了错误的 pnpm 版本。

先确认 pnpm 是 11.19.0，再拉取最新 `main`：

```bash
git pull --ff-only origin main
pnpm install --frozen-lockfile
```

不要直接删除 `pnpm-lock.yaml`。

### 13.4 `Cloudflare D1 binding DB is unavailable`

原因：本地 migration 未执行，或新 Sites 项目没有绑定 `DB`。

本地：

```bash
pnpm db:migrate:local
```

线上：检查 `.openai/hosting.json` 中 `d1` 为 `DB`，并让 Sites 重新保存和部署版本。

### 13.5 Synology 搜索提示未配置或认证失败

检查 `.env.local` 或 Sites 环境变量中的四个 `SYNOLOGY_*` 变量。确认：

- 地址使用 HTTPS；
- 账号未锁定；
- 账号对根目录有只读权限；
- NAS 防火墙允许 Sites 出站访问；
- 密码变化后已同步更新托管环境。

不要把密码打印到日志中。

### 13.6 BMP / 医检所同步返回 502 或 not configured

这通常不是前端故障，而是接口尚未配置。检查 BASE_URL、SERVICE_TOKEN 和资源 PATH，并先向接口负责人确认 `/health`、鉴权头和字段口径。

### 13.7 管理员操作返回 403

当前用户邮箱未列入 `PLATFORM_ADMIN_EMAILS`。由站点所有者在托管环境中添加，多个邮箱使用英文逗号分隔，然后重新部署或刷新运行环境。

### 13.8 导航点击没有反应

先刷新页面，确认使用的是最新部署版本。侧栏采用原生链接以兼容 Sites 路由；如果问题复现，检查 `components/platform-sidebar.tsx` 中是否仍为 `<a href="...">`，并确认所有 `/modules/*` 地址返回 200。

### 13.9 `pnpm build` 失败

按顺序执行：

```bash
nvm use 22.13.0
pnpm install --frozen-lockfile
pnpm lint
pnpm build
```

只处理构建日志中第一个真实错误，不要通过关闭 TypeScript 或跳过 lint 掩盖问题。

### 13.10 GitHub 推送被拒绝 `fetch first`

远端比本地更新。安全做法：

```bash
git fetch origin main
git pull --rebase origin main
pnpm lint
pnpm build
git push origin main
```

如有冲突，逐文件核对后再提交；不要强制推送覆盖他人的改动。

### 13.11 Sites 提示无权访问项目

说明当前账号不是原站点所有者或编辑者。选择其一：

1. 让原所有者增加编辑权限；
2. 按第 4 节创建自己账号下的新副本站点。

不能通过复制临时凭证绕过权限。
