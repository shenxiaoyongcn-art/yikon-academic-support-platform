# 企业微信微盘资料盘点草案（2026-09-05）

> 状态：盘点准备稿
> 依据：用户提供的企业微信微盘截图中可见内容
> 重要说明：本次**没有登录后遍历微盘、没有读取文件正文、没有移动、改名、合并或删除任何文件**。截图以外的目录、权限、文件数量和版本情况均待资料管理员核验。

## 1. 盘点目的

当前资料既有离线文件，也有在线文档，且更新和汇总依赖人工。盘点的目标不是把文件重新复制一遍，而是建立一套可持续维护的资料索引，使学术支持管理平台能够：

- 按模块、医院、产品、项目、会议和资料类型快速查询；
- 找到原文件的受控位置和最新版本；
- 把资料与科研项目、会议、招标、售后、PGT 筹建和培训记录关联；
- 识别重复目录、重复文件、失效链接和无人维护资料；
- 保留企业微信微盘／NAS 原有权限、在线协作和版本历史。

## 3. 已识别的待确认问题

### 3.1 招标目录可能重复

截图中同时出现：

- `3-01-招标相关材料和素材库`
- `招标相关及招标素材库`

两者名称相近，先标记为“疑似重复目录”，不得仅按名称直接合并。管理员需要比较：

- 企业微信文件夹唯一 ID 和实际所属空间；
- 所有者、协作者和访问权限；
- 子目录结构、文件数量、最近更新时间；
- 同名文件的版本、大小、哈希（离线文件适用）和在线文档 ID；
- 是否一处为正式库、一处为历史库或跨部门共享入口。

确认后优先保留一个权威目录；另一处可设置受控快捷入口或标明归档，不直接删除。

### 3.2 命名和口径不统一

- `PGD`、`PGT`、`PGT资质`等术语可能混用；
- “客户维护”可能混入联系人主档，与 BMP 的主数据职责冲突；
- “资料”“公司资料”等宽泛目录难以检索和确定责任人；
- 离线文件与在线文档可能存在内容相同但版本不明的副本。

所有调整先形成“原位置 → 建议位置”的映射表，经资料所有者确认后执行。盘点阶段不改原名。

## 4. 建议的统一目录结构

一级模块可暂时保留现有编号，避免团队找不到资料。每个模块内部建议统一使用以下骨架：

```text
模块目录
├── 00-索引台账
├── 01-制度SOP与模板
├── 02-在办事项
├── 03-交付成果
├── 04-数据与复盘
├── 90-历史归档
└── 99-待分类
```

说明：

- `00-索引台账`：保存该模块的责任人、目录说明、文件清单和变更记录；平台上线后以平台索引为主，微盘可保留便于人工查阅的导出表。
- `01-制度SOP与模板`：只放可重复使用的受控模板和制度，不混入具体项目文件。
- `02-在办事项`：按业务对象稳定编号组织，不只按人员姓名建目录。
- `03-交付成果`：保存经确认的最终成果；草稿仍留在对应在办事项内。
- `04-数据与复盘`：保存已确认口径的汇总和复盘，不把原始数据与派生报告混在一起。
- `90-历史归档`：只读为主，保留原路径映射和归档日期。
- `99-待分类`：临时收口，必须有责任人和清理期限，不能长期变成新的“资料”杂物目录。

### 4.1 会议模块建议细分

会议资料量大且复用频繁，可在 `2-01-推广会议运营` 的统一骨架下增加：

```text
2-01-推广会议运营
├── 00-索引台账
├── 01-年度规划与会议日历
├── 02-会前策划与申请
├── 03-执行资料与物料
├── 04-会后总结与效果跟踪
├── 05-讲题与课件库
├── 06-专家与讲者证明资料
├── 90-历史归档
└── 99-待分类
```

专家／讲者的结构化标签、历史参会记录和评价建议由平台专家库维护；微盘保留授权范围内的课件、授权文件和证明资料。客户联系人主档继续以 BMP 为准。

### 4.2 科研模块建议细分

```text
1-01-科研及项目申报
├── 00-索引台账
```

## 5. 在线文档与文件的处理原则

1. **在线文档继续留在企业微信微盘中编辑**，不下载后重新上传成另一份“最新版本”。
2. 平台只保存企业微信文件／文档唯一 ID、受控链接、当前版本、更新时间和业务关系。
3. 离线 Word、Excel、PPT、PDF、视频等也优先保留原文件 ID；有新版本时通过原生版本能力更新，避免用“最终版、最终版2、最新版”区分。
4. 平台展示的“最新版本”必须来自微盘／NAS 元数据或管理员核验，不能通过文件名猜测。
5. 资料正文的查看、编辑、下载权限仍由微盘／NAS 控制，平台不得用公共直链绕过权限。
6. 文件实际移动后，平台必须更新索引并保留旧路径、迁移批次和操作人，确保历史记录仍可追溯。
7. 对合同、绩效、客户敏感信息、原始数据和遗传相关资料单独设置密级和访问组。

## 6. 平台资料索引的最小字段

| 字段 | 用途 |
| --- | --- |
| `asset_id` | 平台资料稳定编号 |
| `source_system` | `wecom_drive`、`nas`或其他受控来源 |
| `external_file_id` | 企业微信／NAS 文件或在线文档唯一 ID |
| `title` | 展示标题 |
| `module_code` | 科研、会议、招标、售后、PGT、培训、平台、团队等模块 |
| `document_type` | SOP、模板、申请、合同引用、PPT、视频、数据、报告、复盘等 |
| `business_object_type` / `business_object_id` | 关联项目、会议、专家、医院、工作项的稳定编号 |
| `hospital_id` | BMP 医院 ID；没有时进入待匹配状态 |
| `product_code` | BMP 产品代码；支持多值关系，不用逗号文本代替长期模型 |
| `region_code` | BMP 区域代码 |
| `owner_user_id` | 资料责任人的稳定用户 ID |
| `confidentiality` | 公开范围、部门、项目组、敏感、严格受限等 |
| `lifecycle_status` | 草稿、受控、已发布、已替代、已归档 |
| `version` | 来源系统版本或人工核验版本 |
| `url_or_path` | 受控链接或路径，不保存公开永久直链 |
| `source_updated_at` / `synced_at` | 来源更新时间和平台同步时间 |
| `verified_by` / `verified_at` | 最近核验人和核验时间 |
| `supersedes_asset_id` | 新版本替代的旧资料编号 |
| `source_location_before_move` | 迁移前位置，支持回溯和回滚 |

文件名、医院名和人员姓名不是唯一键。多模块共用的资料只保留一份权威文件，通过索引建立多个业务关联，避免物理复制。

## 7. 盘点台账建议字段

正式盘点时，建议逐项导出或登记：

- 所属共享空间、父目录、原始完整路径；
- 文件夹／文件／在线文档唯一 ID；
- 名称、类型、大小、创建时间、最近更新时间；
- 所有者、维护责任人、协作者、可见范围；
- 模块、业务对象、医院、产品、区域、年度；
- 生命周期状态和保留期限；
- 当前是否仍使用、是否有新版本、是否存在失效链接；
- 离线文件哈希或等效指纹，在线文档版本 ID；
- 疑似重复组、建议权威版本及判断依据；
- 建议目录、建议动作、确认人、确认日期；
- 实际迁移批次、操作人、结果和回滚位置。

盘点表必须保留原始路径和来源 ID，不覆盖原始证据。

## 8. 执行顺序

### 第一步：确认范围和责任人

- 由资料管理员确认哪些共享空间属于本次学术支持盘点；
- 为科研、会议、招标、售后、PGT、培训、平台和团队资料分别指定业务责任人；
- 确定敏感目录和不可迁移目录。

### 第二步：只读导出元数据

- 先导出目录、文件 ID、所有者、权限、时间和版本，不读取非必要正文；
- 建立截图可见目录与真实目录 ID 的对应关系；
- 不在此阶段移动、改名或删除。

### 第三步：分类和查重

- 先按来源 ID 判定同一在线文档，再按哈希识别相同离线文件；
- 同名但内容不同、内容相同但权限不同的资料进入人工核验；
- 对疑似重复的两个招标目录形成专门差异清单。

### 第四步：确认权威版本与目录映射

- 业务责任人确认哪一份是当前受控版本、哪些可归档；
- 形成“原路径 → 建议路径 → 保留／移动／快捷入口／归档”的变更清单；
- 先确认权限继承和旧链接影响，再批准迁移。

### 第五步：小范围试点

- 建议先选一个资料结构清晰、风险较低的模块试点；
- 每次变更保留迁移批次、操作人、旧位置和回滚方案；
- 验证在线文档协作、历史链接、移动端访问和平台索引均正常。

### 第六步：平台接入与持续治理

- 平台导入确认后的资料索引，按业务对象建立关联；
- 设置失效链接、长期未核验、无人负责和待分类资料提醒；
- 每月处理 `99-待分类`，每季度复核权限、版本和历史归档；
- 新资料尽量从对应业务流程生成或关联，减少再次回到自由建目录。

## 9. 本轮明确不做的动作

- 不根据截图推断文件内容、数量或完整性；
- 不下载在线文档另存为本地副本；
- 不将全部资料上传到学术支持平台数据库；
- 不把客户联系人资料从 BMP 复制为平台主档；
- 不直接合并两个名称相近的招标目录；
- 不批量改名、移动、删除或修改权限；
- 不把患者、样本或遗传数据纳入普通资料盘点。

完成只读元数据盘点、责任人确认和目录映射会签后，才进入实际整理阶段。
