# 亿康科研项目管理工作台｜IT 对接与验收交付说明

版本：2026-09-05
状态：业务工作台可运行，BMP 接口与组织级上线条件待 IT 联合验证

> 本文档必须与 [《学术支持管理平台与 BMP 系统架构边界 ADR》](./PLATFORM_BMP_ARCHITECTURE_BOUNDARY_2026-09-05.md) 一并阅读。若其他历史说明与该 ADR 冲突，以 ADR 及公司最新确认口径为准。

## 1. 一句话定位

科研模块不是第二套 BMP，也不是新的公司级审批系统；它是**学术支持部科研需求评估与项目协同工作台**。

- **BMP 是唯一主系统**：客户、医院、客户联系人、销量、预算包、公司正式审批、合同/财务执行及其最终状态均以 BMP 或公司指定系统为准。
- **本平台负责部门工作**：科研需求收集、完整性核验、专业评估、成本测算、项目责任人快照、部门协同、里程碑、月度进展、资料索引、成果复盘和 AI 辅助分析。
- **文件内容留在受控存储**：企业微信微盘、NAS 或公司云盘保存原文件；平台保存文件 ID、路径、版本、业务关联和访问状态，不建立另一套无权限治理的文件副本。
- **正式动作回到 BMP**：需要预算占用、公司审批、合同、付款、采购、报销或正式项目编号时，由 BMP／ERP／公司指定系统发起或承接；平台只保存外部对象 ID、流程实例 ID、只读状态快照、回执和引用核验记录。

平台中的“同意”“通过”“编号”等字样，如果没有明确的 BMP／ERP 对象 ID、流程实例 ID 和已验证成功回执，只表示**部门内部工作状态、演练结果或外部引用待核验**，不产生公司级审批、财务、合同或对外承诺效力，不得对外表述为“已正式完成”。本平台不设“本地预算占用”口径，只显示 BMP 预算只读快照和独立的项目成本预测基线。

## 2. 系统边界与数据归属

| 数据 / 能力 | 权威主系统 | 本平台可做 | 本平台不得做 |
| --- | --- | --- | --- |
| 账号、组织、岗位、角色 | BMP / 公司统一身份系统 | 接收身份和授权映射，记录本平台操作人 | 自建与 BMP 冲突的正式组织账号 |
| 客户、医院、客户联系人 | BMP / CRM | 按 BMP 对象 ID 查询、缓存展示；项目内保存责任与重要程度快照 | 独立维护第二套客户或联系人主档、按名称造新客户 |
| 销量、订单、回款等经营事实 | BMP / CRM / ERP | 只读调用、分析、形成科研投入产出参考 | 改写销量、把推算结果写回为正式经营事实 |
| 预算包、预算余额、正式占用 | BMP / 财务系统 | 只读查询快照并做可行性校验；展示来源版本和 BMP 回执 | 本地扣减、锁定或释放 BMP 预算；根据成本预测计算或展示第二套“可用余额” |
| 项目成本预测基线 | 本平台 | 记录设备、耗材、检测、分析、人力、管理和协作成本的预测、依据、版本和变更 | 将成本预测表述为预算余额、占用、核销或财务总账；用它扣减 BMP 余额 |
| 科研需求、评估、成本测算 | 本平台 | 创建、补充、评估、形成部门建议和过程记录 | 把部门评估直接等同公司立项审批 |
| 公司正式审批、合同、付款、报销 | BMP / ERP / 合同或财务系统 | 发起跳转或已验收对接；保存真实外部对象 ID、只读状态快照、回执及引用核验记录 | 在本平台完成或模拟具有公司效力的正式审批；将“引用已核验”等同“外部审批已通过” |
| 项目里程碑、月度进展、成果复盘 | 本平台 | 维护执行事实、责任、风险、下一步和成果 | 以无证据文字替代交付、验收或正式结题凭证 |
| 资料原文件 | 企业微信微盘 / NAS / 公司云盘 | 建立资料索引、版本、标签、项目关联和权限提示 | 无授权复制患者数据或绕过原存储 ACL |
| AI 输出 | 本平台派生数据 | 检索、归类、摘要、成本/进度提示、汇报初稿 | 自动审批、篡改源事实、输出无依据的临床诊断或经营结论 |

### 2.1 项目联系人采用“BMP 主档 + 项目快照”

医院相关科研项目必须区分：

1. **医院端项目负责人 / PI**：对项目目标、资源与关键决策负责；
2. **医院端日常对接人**：负责资料、样本、排期与日常协调。

人员基本档案继续由 BMP 维护。本平台通过 `BMP/CRM contactId` 选择人员，并在项目中冻结以下快照：项目角色、具体责任、重要程度、判断依据、记录时间和记录人。主档后续改名或调岗不反向覆盖历史项目快照；如需更换项目人员，应形成项目变更记录。

纯内部 B 类研究可不关联医院人员；一旦使用医院样本、数据、资源或承诺医院交付，必须补齐上述双角色及依据。

## 3. 科研业务路由

三类路由用于学术支持部识别业务性质、评估风险和准备 BMP 正式流程。路由中的“预审”“会签建议”“通过”均为部门协同状态，除非已收到 BMP 正式回执。

### A 类：客户科研 / 公司投入

需求草稿 → 完整性核验 → 专业可行性评估 → 分析与资源评估 → 项目成本预测基线 → BMP 预算只读快照校验 → 大区业务意见 → 营销建议 → 适用的合规/例外建议 → 立项条件清单 → 向 BMP 提交正式审批 → 启动协同 → 执行 → 验收资料 → 成果与投入产出复盘。

关键点：

- 判断医院潜力、客户背景、项目价值、预计样本、学术产出和业务关联，说明“值不值得投入”。
- 设备、耗材、检测、分析、人力、项目管理及协作成本必须形成可追溯的项目成本预测基线；它不等于财务记账，不扣减 BMP 余额，不产生平台“可用余额”。
- 超预算、重大承诺或高风险项目必须在 BMP 走单项正式审批，不得凭平台内部状态启动公司级资源投入。

### B 类：课题研究 / 战略研发

需求 → 完整性核验 → 专业及成本评估 → 指定 Sponsor → 产品/研发意见 → 医院或跨区域资源确认（条件） → 重大外部承诺确认（条件） → PMO 整理立项材料 → 向 BMP 提交正式审批 → 研发节点执行 → Sponsor 阶段决策 → 成果验收与复盘。

关键点：

- 无 Sponsor、战略目标或成果定义，不进入正式立项准备。
- PMO 负责流程完整、进度和风险，不替代 Sponsor、研发或公司审批人作专业决定。
- 纯内部项目与客户收费项目必须分开；收费、合同、开票、回款等事实以 BMP/ERP 为准。

### C 类：临床收费 / 过渡生产

需求 → 完整性核验 → 大区确认真实收费需求 → 产品/市场前置评估 → 研发可实现性 → 分析及成本 → 商务/财务建议 → 质量/法规/医学建议 → 临时通路或科研登记材料 → 向 BMP 提交正式审批及报价/合同流程 → 执行 → 报告与转产/退出节点 → 验收复盘。

关键点：

- 产品/市场前置判断未完成，不能进入研发执行准备。
- 临时通路必须有失效日期、转产或退出责任人，不得默认无限续期。
- 收费项目只有取得适用的 BMP/ERP 报价、合同、支付或授信依据后，才能被标记为“正式启动”；平台内部记录不能代替这些凭证。

## 4. 本期可运行能力

入口：`/modules/research`；模块接口：`/api/research`。

### 4.1 正式工作区

- 创建 A/B/C 科研需求草稿，按角色和当前节点保存、退回、储备、等待、恢复、变更和终止；
- 完整性、专业、成本、路由和项目联系人门禁；
- 医院项目负责人及日常对接人项目快照；
- 项目成本预测基线与 BMP 预算包只读快照校验；两者分开展示，不计算第二套可用余额；
- 里程碑、交付证据、验收意见、异常和提醒；
- 月度进展：本月动作、风险、下一步、需支持事项和关联里程碑；
- 资料索引：微盘/NAS/云盘路径、外部文件 ID、版本、类别、里程碑、有效状态和归档；
- BMP/ERP 单据引用：核验报价、订单、合同、付款、报销、资源和费用等外部对象的真实 ID、来源状态、版本和回执；平台不设本地正式审批；
- 例外审批、预算调整和财务收口的正式回执 ID／状态不在工作区表单中手工录入；只能由已验收的 BMP／ERP 入站对接更新；
- 操作历史、修订号、权限过滤和审计快照；
- Excel 批量导入为**平台草稿**，保留来源和异常，不自动形成正式立项或 BMP 审批结果。

### 4.2 流程设计预览

预览使用虚拟项目、虚拟医院和虚拟预算，只用于业务讨论和角色演练，刷新可重置。它与正式工作区共享流程规则，但不写入正式记录，不生成 BMP 对象，不代表真实审批。

### 4.3 当前必须如实标识的状态

- 当前代码可在本地环境运行并进行规则测试；
- BMP 的真实 API、SSO、对象字段、审批接口、技术栈和测试环境尚未取得完整资料并验证；
- `lib/integrations/bmp.ts` 是可配置的读取适配器和占位契约，不是已验证的生产接口；
- `research_outbox` 仅记录待对接事件，当前没有生产 worker 外发，也没有可靠回执闭环；
- 旧通用科研端点 `/api/work-items/research` 的读写均返回 HTTP 410；正式科研工作区只使用 `/api/research` 和 `research_cases_v2`，不再产生第二套可写科研台账；
- 科研聚合中已分开保存平台流程状态与 `BmpCaseLink`；`BmpCaseLink` 包含对接状态、BMP 正式立项决策／流程实例、预算回执 ID／状态、财务收口回执 ID／状态和源版本；
- 由于上述 BMP／ERP 入站回执尚未生产接通，正式工作区中依赖它们的例外、预算调整、启动和财务收口节点必须阻断；这是安全门禁，不是已实现的 BMP 联动；
- 客户、联系人、预算、销量和医检所数据必须同时具备外部对象 ID、源版本、源更新时间、同步时间及逐行核验状态后才能进入正式工作区或 AI 分析；历史行默认不可信，不因全局开关自动升级；
- 因此不得声称“已接通 BMP”“已完成预算占用”或“已在 BMP 正式立项”。

## 6. 接口与同步契约

### 6.1 统一原则

1. 不直接写 BMP 数据库，只使用 IT 提供并授权的 API、消息或标准交换文件。
2. 所有 BMP 对象使用稳定对象 ID；禁止以医院名、联系人姓名、项目名作为唯一键。
3. 每条外部数据至少记录：来源系统、对象 ID、源更新时间、同步时间和源版本。
4. 出站幂等键建议为 `caseId + revision + eventType`；BMP 返回外部对象 ID、流程实例 ID、处理状态、版本和回执时间。
5. 重试不得重复立项、占预算、付款或创建合同；版本冲突进入人工处理，禁止“最后写入覆盖”。
6. 状态必须以三组独立字段保存和展示，不得合并为一个 `status`：`platform_status` 只表示平台业务进度，`integration_status` 只表示传输/同步进度，`bmp_status` 只表示 BMP 正式回执状态。
7. `bmp_status` 只能由匹配 BMP 对象的已验证回执更新；未收到回执时保持“未知/未同步”，不得由 `platform_status`、`integration_status` 或 HTTP 200 推导。
8. 科研模块中，`Case.stage` 对应平台流程状态；`Case.bmp.integrationStatus` 对应对接状态；`Case.bmp.officialDecision`、`bmpWorkflowInstanceId`、`budgetReceiptId/budgetReceiptStatus`、`settlementReceiptId/settlementStatus` 对应 BMP 正式事实。后一组不得通过正式工作区表单写入。

| 状态层 | 字段 | 示例 | 唯一可信更新来源 |
| --- | --- | --- | --- |
| 平台流程状态 | `platform_status` | 草稿、部门评估中、建议立项、执行协同中、结题 | 本平台受权业务操作 |
| 对接状态 | `integration_status` | 未提交、待发送、已发送、已接收、失败待处理 | 平台集成层及幂等回执 |
| BMP 正式状态 | `bmp_status` | 待审批、审批中、已通过、已驳回、已撤回、已终止 | BMP 已验证业务回执 |

### 6.2 BMP 入站数据

优先确认并逐步接入：

- 统一身份、组织、角色和大区；
- 客户/医院及联系人主档；
- 销量、订单、回款等只读经营数据；
- 预算包、额度和正式占用状态；
- 历史科研立项、主项目、子中心、节点、审批日志和外部单据；
- BMP 审批流程及执行状态回调。

### 6.3 平台出站数据

平台向 BMP 提交的是经过学术支持部整理的业务材料，而不是直接修改正式主数据：

- 科研需求、路由、医院、产品和目标；
- 专业评估、成本测算、资源需求及风险；
- 医院端项目负责人/对接人引用与项目责任快照；
- Sponsor、PMO、内部协同责任人；
- 立项条件、附件索引和变更说明；
- 需要 BMP 发起的正式审批、预算、合同、付款、采购或报销事项。

## 7. 历史数据与 Excel 导入

历史 BMP 数据和部门 Excel 只能先进入暂存/草稿层，不得直接映射成“已批准”“已立项”“预算已占用”或“已结题”。

迁移步骤：

1. 保存源文件、源系统、源表、源行号、导入批次、原始值和文件哈希；
2. 以 BMP 客户 ID、联系人 ID、项目 ID 为主进行匹配；名称仅用于人工候选；
3. 合并重复主项目和多中心记录，保留旧编号与来源关系；
4. 把缺少外部对象 ID、审批日志、预算回执或关键联系人信息的记录列入待核对清单；
5. 业务确认映射后再导入正式工作区；未核验数据保持“历史待核验”；
6. 迁移后抽样比对项目数、中心数、金额、状态、负责人和最近节点，保留可回滚批次。

Excel 导入使用客户端行 ID 或源系统唯一键保证重试去重；同一记录重复导入不得覆盖已有人工作业。导出结果需保留平台 ID、BMP ID、状态层级、更新时间和异常说明。

## 8. 权限、审计与安全

- 读取需登录并具有科研模块权限；写入另校验角色、区域/团队范围、当前节点和期望修订号。
- 医院联系人联系方式按最小必要原则返回；项目快照只保存业务角色、责任、重要程度和依据，不复制不必要的联系方式。
- 销售、大区、研发、产品、财务、质量和 PMO 只办理各自职责范围；平台角色不能绕过 BMP 组织授权获得公司级审批权。
- 所有关键动作记录操作人、时间、前后修订、意见、证据、来源 IP/会话信息（按公司安全规范）和外部回执。
- 已生效记录采用追加修订和停用，不物理覆盖历史；导入、变更、退回、终止、资料归档均应可追溯。
- 密码、令牌、患者数据和受控文档内容不得进入日志、Excel 导入错误信息或 AI 提示词；原文件访问继续服从微盘/NAS/云盘 ACL。
- 正式环境须使用公司 SSO 或可信认证网关；不得信任公网客户端自行提交的身份头。

## 9. IT 必须确认的事项

在任何“已对接”或生产上线结论前，IT 需书面确认：

1. BMP 前后端技术栈、部署方式、版本策略和可扩展边界；技术语言是否一致不是关键，稳定 API 契约才是关键。
2. SSO/登录协议、用户唯一 ID、组织/岗位/角色、大区及代理授权规则。
3. 客户、医院、联系人、销量、预算、科研项目、中心、审批实例和单据的对象 ID、字段字典、状态字典。
4. 对象合并、改名、停用、软删除和历史追溯规则。
5. OpenAPI/消息机制、鉴权、分页、限流、超时、错误码、幂等、回调签名和重试约定。
6. 预算包查询、预算正式占用/释放、公司审批、合同、付款、报销的归属系统和允许的调用方式。
7. BMP 科研立项/管理现存流程的实际节点、字段、卡点，以及哪些保留、替换或由本平台补充。
8. 文件中心或企业微信微盘的外部文件 ID、分享链接、ACL、版本、审计和失效规则。
9. 测试环境、脱敏测试数据、联调账号、验收责任人、发布窗口、监控和回滚方案。
10. 当前 `research_outbox` 的消费方、事件契约、失败重试、死信和回执更新机制。

未获得上述资料前，只能验证平台内部工作流，不能推断 BMP 架构语言，也不能承诺代码可直接无缝合入 BMP。

## 10. 联调与 UAT 验收

### 10.1 平台内部 UAT

| 场景 | 必须通过的结果 |
| --- | --- |
| A 类需求评估 | 医院背景、潜力、双联系人、成本及依据齐全；缺项不能完成部门评估 |
| B 类 Sponsor | 无 Sponsor 拒绝推进；PMO 不能替 Sponsor 作专业决策 |
| C 类过渡项目 | 产品/市场在研发前；失效日、转产/退出责任人和条件明确 |
| 项目联系人 | BMP 人员引用与项目快照分离；变更保留旧快照 |
| 成本测算 | 设备、耗材、检测、分析、人力、管理和协作成本可追溯，不冒充财务数据 |
| 月度进展 | 能记录动作、里程碑、风险、下一步和需支持事项；按月份和项目查询 |
| 资料索引 | 能关联外部文件 ID、路径、版本和里程碑；归档不删除原存储文件 |
| Excel 导入 | 只生成草稿；重复导入不重复建项；异常行可下载核对 |
| 变更/终止 | 原记录、原基线和历史不丢；已发生事项不被静默抹除 |
| 权限审计 | 越权读取/办理被拒绝；操作历史和修订冲突可追溯 |

### 10.2 BMP 联调 UAT

| 场景 | 必须通过的结果 |
| --- | --- |
| 主数据读取 | 通过稳定 ID 取得客户/联系人，改名和停用可同步且不破坏项目快照 |
| 销量读取 | 时间、产品、医院、口径与 BMP 页面/报表一致，空值不补零 |
| 预算校验 | 只显示 BMP 只读快照、源版本和更新时间；项目成本预测基线独立展示，不扣减 BMP 余额，不生成平台可用余额 |
| 正式审批提交 | 返回 BMP 对象 ID 和流程实例 ID；重复请求只产生一个实例 |
| 状态回调 | 审批中、批准、退回、撤回、执行和异常状态可正确映射 |
| 外部单据 | 报价、订单、合同、付款、报销、资源和费用只做 BMP/ERP 真实 ID、状态、版本和回执的引用核验；页面不提供本地正式审批；项目收口后也不得自动把费用核销标成完成 |
| 断线重试 | 不重复立项、占预算、付款或建合同；失败可人工重放并审计 |
| 文件访问 | 链接、权限、版本和失效符合原存储 ACL，未授权用户不可下载 |
| 历史迁移 | 抽样记录的项目、中心、金额、状态、人员、节点和来源可对账 |

### 10.3 状态验收硬门槛

以下三个条件缺一，不得显示或汇报为正式完成：

1. 匹配的 BMP/ERP 对象 ID；
2. 匹配的流程实例 ID 或业务执行单据；
3. 已校验的成功回执、最终状态和回执时间。
